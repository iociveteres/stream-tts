# Stream TTS: развёртывание

Часть спецификации [stream-tts.md](stream-tts.md): как запускается сервис и откуда берёт сервер синтеза, модель и
голоса. Программа для Windows — [stream-tts-windows.md](stream-tts-windows.md).

## Режимы

Два режима работы с сервером синтеза, ядро одно. Моделей две — CosyVoice3 (cosyvoice-server) и ESpeech
(espeech-server, [espeech.md](espeech.md)), работает одна, выбранная на вкладке «Сервер» (`settings.engine`;
спецификация — [stream-tts.md](stream-tts.md), «Модели синтеза»):
- **external** — задан `COSYVOICE_URL` или `TTS_SERVERS=cosyvoice=http://…,espeech=http://…`: серверы запущены
  отдельно (другая машина, профиль `server-only`), `COSYVOICE_URL` — то же, что `cosyvoice=…`. Модель и голоса
  ставятся на них. Вкладка «Сервер» есть, только если моделей несколько (выбор модели и её настройки).
- **managed** — `COSYVOICE_URL` не задан, а рядом есть нативный `cosyvoice-server(.exe)` (папка `runtime/` рядом с
  программой, в исходниках — в корне проекта, в образе Docker — `/opt/cosyvoice` через `STREAM_TTS_RUNTIME`, или
  путь в `COSYVOICE_SERVER`). Так работают программа для Windows и `docker-compose.yml`. stream-tts сам запускает
  сервер (адрес `COSYVOICE_HOST`, по умолчанию `127.0.0.1`; порт — свободный или `COSYVOICE_PORT`), ходит к нему по
  `127.0.0.1`, перезапускает при падении и завершает при выходе (на Windows через Job Object, даже если stream-tts
  убит, на Linux через `PR_SET_PDEATHSIG`). Аргументы — как в `cosyvoice/entrypoint.sh` (`engines/cosyvoice/launch.py`): модель
  (`MODEL` или единственный `*.gguf` в папке моделей; без модели сервер ждёт её появления), голоса `*.gguf` из папки
  голосов и её подпапок-наборов (имя голоса — имя файла), пути ONNX-фронтенда из `<модели>/frontend-onnx` (сам
  фронтенд грузится, только когда создаётся голос), проверка AVX2.
  Бэкенд выбирается по `cosyvoice-cli --list-backends`: CUDA, если есть `ggml-cuda` и видеокарта NVIDIA, иначе
  Vulkan (дискретная раньше встроенной), иначе CPU; `COSYVOICE_BACKEND=cuda|vulkan|cpu` задаёт его явно. Всегда
  `GGML_CUDA_DISABLE_GRAPHS=1`, на CUDA ещё `--llm-flash-attn 0`. В админке рядом с адресом сервера видны
  «встроенный», бэкенд, модель и число голосов.
  ESpeech (`engines/espeech/launch.py`): `python -m espeech` интерпретатором его окружения — `ESPEECH_SERVER` (путь
  к `python(.exe)` или папке с ним), иначе `runtime/espeech/` (поставка — позже), иначе `espeech/.venv` проекта;
  `--models <модели>/espeech` (без весов сервер ждёт, причина — в админке), `--voices <голоса>`, `--device cuda`, если
  есть драйвер NVIDIA (`ESPEECH_DEVICE=cpu|cuda` или выбор в админке). Встроенный сервер один: смена модели
  перезапускает его с другим движком на том же порту (`COSYVOICE_PORT` или `ESPEECH_PORT` модели, выбранной при
  запуске, иначе свободный).

## Первый запуск (режим managed)

Вкладка «Сервер» в админке (`install.py`), без модели админка открывается сразу на ней:
- **Модель.** Карточки квантов Q8_0 (по умолчанию), Q6_K и Q5_K_M (`QUANTS` в `install.py`): размер файла,
  видеопамять и пример звука (`static/quants/<голос>-<квант>.mp3`, синтез с seed 42). Голос примеров
  `ohf-denis` — из датасета [ru_RU-denis](https://github.com/OHF-Voice/voice-datasets) (CC0: записи, переданные
  добровольцами для синтеза речи Home Assistant), поэтому mp3 лежат в git и в установщике. Образец — четыре
  реплики из `ru-RU/3000000001_3000000300_Chat` (3000000223, 026, 112, 274), склейка 10,8 с, 24 кГц; синтез —
  cosyvoice-server на CPU, mp3 24 кГц 48 кбит/с. Видеопамять — пик cosyvoice-server на CUDA, RTX 3060 Ti, 2026-10-17: обычно / на самом длинном
  образце (***, 21,7 с) — Q8_0 ≈1,5 / 1,9 ГБ, Q6_K ≈1,45 / 1,8 ГБ, Q5_K_M ≈1,3 / 1,7 ГБ; на Vulkan пик примерно
  на 0,5 ГБ больше. На 54 фразах (6 голосов × 3 фразы × 3 seed) расшифровка Whisper (cer 0,011–0,017) и сходство
  CAM++ (0,810–0,820) у трёх квантов в пределах шума. Остальные кванты — `scripts/download-model.sh`; положенный
  вручную `*.gguf` тоже виден в списке и выбирается кнопкой «Использовать». Загрузка — как в
  `scripts/download-model.sh`: файл с Hugging Face пишется в `<имя>.part` с докачкой по Range и пятью повторами,
  сверяется с sha256 из заголовка `x-linked-etag` и только потом переименовывается. Прогресс, скорость и остаток
  времени видны в админке; «Отменить» оставляет `.part`, следующее «Скачать» продолжает с того же места. ONNX-фронтенд
  — дополнительный пакет в настройках ([stream-tts.md](stream-tts.md), «Голоса»): для озвучки он не нужен. После загрузки модель выбирается (`settings.model`) и сервер
  запускается сам. Из нескольких установленных моделей используется выбранная. Квант, выбранный в установщике
  (`setup-model.txt` в папке программы), качается сам при первом запуске без модели — один раз
  (`settings.setup_download`), отмена его не перезапускает.
- **Устройство синтеза**: «Автоматически», CUDA, Vulkan или процессор (`settings.backend`); варианты, которых нет на
  машине, недоступны. Смена перезапускает сервер. `COSYVOICE_BACKEND` и `MODEL` выбор в админке перекрывают.
- **Скорость синтеза** (`bench.py`) — замер на машине стримера вместо чисел из нашей разработки. «Проверить
  текущее»: короткая фраза-разогрев, затем фраза ~6 с целиком (скорость = длина звука / время синтеза) и она же
  стримингом с текущим `chunk_tokens` до первого куска (задержка первого звука, дальше `/tts/stop`). «Сравнить все
  устройства» — то же на CUDA, Vulkan и CPU по очереди с перезапуском сервера, в конце возвращается выбранное
  устройство. Всё время проверки доступ к cosyvoice занят с приоритетом «послушать», так что озвучка ждёт в очереди
  и не попадает на перезапуск; во время озвучки проверка не запускается. Результат — последний замер на пару
  устройство + модель (`settings.bench`), ячейка скорости зелёная от ×2, жёлтая от ×1,1, красная ниже.
  На RTX 3060 Ti, Q8_0, 2026-10-18, три прогона: CUDA ×3,7–4,7 (первый звук 1,3–1,6 с), Vulkan ×2,8–4
  (1,4 с), CPU ÷4,5 (31 с).
- **Наборы голосов** — zip с голосами (`*.gguf` CosyVoice, `*.espeech` ESpeech) и `manifest.json` (ключи — имена
  голосов: `title`, `post`…) в корне архива или в одной папке; обычно это коллекция одной модели одного источника
  (`voice-sets/<модель>/<набор>.zip`, `tools/voices/pack-sets.py`). Имя набора — эта папка или имя zip (латиница,
  цифры, `-`, `_`), оно же группа на странице голосов. Набор ставится в `<голоса>/<набор>/`: голоса обеих моделей
  одного набора лежат в одной папке, повторная установка заменяет голоса только тех моделей, что есть в zip, а
  записи манифеста голосов, у которых не осталось файлов, убираются. В списке наборов — строка на модель («wc3 ·
  ESpeech»), «✕» удаляет голоса этой модели (последней — вместе с папкой). Голос с именем, которое у этой модели уже
  есть в другом наборе или без набора, пропускается; файлы не на верхнем уровне и не голоса игнорируются, `.gguf`
  проверяется по сигнатуре, `.espeech` — по заголовку safetensors; голос — до 64 МБ, архив — до 2 ГБ (адаптер LoRA
  ESpeech ~10 МБ). Пока файлы меняются, сервер остановлен (на Windows он держит `.gguf` открытыми),
  затем запускается с новым списком; stream-tts перечитывает голоса после каждого запуска сервера, примеры новых
  голосов синтезируются в фоне. `post` из `manifest.json` может ссылаться только на `effects/*.py`. Zip грузится
  сырым телом (`Content-Type: application/zip`, имя в `X-Filename`): такой запрос с чужой страницы требует
  CORS-проверки, как и JSON.

## Рантайм и пути

Рантайм для Windows (проверено 17.10.2026 на RTX 3060 Ti): cosyvoice.cpp v0.2.0
(`cosyvoice-67d45fe-windows-x64-ffmpeg.zip`), GGML из llama.cpp b11500 (`ggml*.dll` со всеми `ggml-cpu-*.dll`,
`libomp.dll`; `ggml-cuda.dll` с `cublas64_13`, `cublasLt64_13`, `cudart64_13` из `cudart-llama-bin-win-cuda-13.4-x64`;
`ggml-vulkan.dll`), ICU 78 (`icudt78`, `icuuc78`, `icuin78`), FFmpeg 8.1 lgpl-shared (DLL и `ffmpeg.exe`), рантайм
VC++ 14.51+ (cosyvoice собран тулсетом 14.51; со старым `msvcp140.dll` не запускается). Ядро без бэкендов GPU —
188 МБ, CUDA — ещё 664 МБ, Vulkan — 45 МБ. Скорость (RTF, фраза целиком):
CUDA 0,22–0,32, Vulkan 0,22–0,38 (первый запрос на новой машине ~35 с — компиляция шейдеров, кэш драйвера живёт
между запусками), CPU 4–9.

Пути (`paths.py`). Из исходников проекта — как раньше: `stream-tts-data/`, `models/`, `voices/`, `voice-refs/` (манифесты
`voice-refs/<модель>/<набор>/manifest.json`),
`runtime/` в корне. Программа, поставленная установщиком (рядом с exe лежит файл-признак `portable`), хранит всё
в своей папке: данные — `data\`, модели — `models\`, голоса — `voices\`; собранная программа без признака (например,
`build-exe.py --runtime`) — в `%LOCALAPPDATA%\StreamTTS\` (Linux: `$XDG_DATA_HOME/stream-tts`). Код и статику она
только читает. Всё переопределяется переменными `STREAM_TTS_DATA`,
`STREAM_TTS_MODELS`, `STREAM_TTS_VOICES`, `STREAM_TTS_PROJECT`, `STREAM_TTS_RUNTIME`. ffmpeg ищется в рантайме и
рядом с программой, потом в `PATH` (или `FFMPEG`).

## Docker

Сервис `stream-tts` в `docker-compose.yml` — режим managed со встроенным сервером из того же образа (корневой
`Dockerfile`, цель `stream-tts`), `restart: unless-stopped`. Возможности те же, что у программы для Windows:
вкладка «Сервер», наборы голосов из zip, загрузка пакетов, выгрузка модели, очистка образца от музыки; CUDA уже в
образе `stream-tts:cuda` (`docker-compose.gpu.yml`), скачивать её не нужно. Проверка обновлений выключена:
обновление — `git pull && docker compose up -d --build`.

- Образ: `ubuntu:26.04` (glibc 2.43 для cosyvoice.cpp), Python 3.14 из apt в venv `/opt/venv`, ffmpeg, aiohttp,
  numpy, onnxruntime; сервер — `/opt/cosyvoice`. На CUDA образ больше на объём рантайма CUDA.
- Пути: `STREAM_TTS_RUNTIME=/opt/cosyvoice`, `STREAM_TTS_MODELS=/models`, `STREAM_TTS_VOICES=/voices`,
  `STREAM_TTS_DATA=/data`, `STREAM_TTS_PROJECT=/project`.
- Тома: `./stream-tts-data:/data` (SQLite, настройки, токены, кеш примеров), `./models:/models` и `./voices:/voices`
  с записью (админка качает модели и ставит наборы), `voice-refs/` и `effects/` (скрипты эффектов) только для
  чтения. Режим `cut` в `effects/villager-fx.py` звуки жителя не читает. Остальным режимам нужна
  `voice-origs/minecraft-villager/`.
- Порты: 8090 — интерфейс и оверлей, 8080 (`PORT`) — WebUI и API сервера для `scripts/` и `tools/`, оба на
  `127.0.0.1`. Сервер в контейнере слушает `0.0.0.0` (`COSYVOICE_HOST`), порт `COSYVOICE_PORT=8080`.
- Перезапуск stream-tts перезапускает и сервер (модель и голоса грузятся за несколько секунд), `docker stop`
  завершает оба. Сервер ненадолго останавливается и при установке или удалении набора, выгрузке модели, смене
  модели или устройства и проверке скорости.
- `MODEL` в stream-tts не передаётся: он закрепил бы модель и отключил выбор в админке. При нескольких `*.gguf` в
  `models/` модель выбирается на вкладке «Сервер» (`settings.model`).

**Профиль `server-only`** — только cosyvoice-server, как раньше: `docker compose up -d cosyvoice` (цель
`cosyvoice`, `cosyvoice/entrypoint.sh`). Он занимает тот же порт 8080 и видеокарту, поэтому stream-tts перед ним
останавливают. Модель — `MODEL` или единственный `*.gguf`, голоса из подпапок получают имя через `_`
(`voices/wc3/thrall.gguf` → `wc3_thrall`), а у встроенного сервера имя голоса — имя файла.

## Переменные

Переменные `.env` (в программе для Windows — `stream-tts.env`, см. [stream-tts-windows.md](stream-tts-windows.md)):

| Переменная | По умолчанию | Зачем |
|---|---|---|
| `STREAM_TTS_PORT` | `8090` | порт интерфейса и оверлея |
| `STREAM_TTS_BIND` | `127.0.0.1` | `0.0.0.0`, чтобы OBS на другом ПК дотянулся по сети |
| `STREAM_TTS_PASSWORD` | — | пароль админки; обязателен, если `BIND` не localhost |
| `STREAM_TTS_LANG` | язык установщика, иначе `ru` | `ru` или `en`: язык при первом запуске, дальше — переключатель в админке |
| `COSYVOICE_URL` | — | внешний сервер CosyVoice; без него и `TTS_SERVERS` — режим managed |
| `TTS_SERVERS` | — | внешние серверы моделей: `cosyvoice=http://…,espeech=http://…` (выбор модели — в админке) |
| `ESPEECH_SERVER` | `espeech/.venv` проекта | managed: python окружения espeech-server или папка с ним |
| `ESPEECH_DEVICE` | `auto` | managed: `cuda` или `cpu` для ESpeech |
| `ESPEECH_PORT`, `ESPEECH_HOST` | свободный, `127.0.0.1` | managed: как `COSYVOICE_PORT` и `COSYVOICE_HOST`, если при запуске выбрана ESpeech |
| `COSYVOICE_SERVER` | `runtime/cosyvoice-server(.exe)` | managed: путь к серверу или его папке |
| `COSYVOICE_BACKEND` | `auto` | managed: `cuda`, `vulkan` или `cpu` |
| `COSYVOICE_PORT` | свободный, `8080` в Docker | managed: порт сервера |
| `COSYVOICE_HOST` | `127.0.0.1`, `0.0.0.0` в Docker | managed: адрес, на котором слушает сервер (stream-tts ходит к нему по `127.0.0.1`) |
| `MODEL` | выбранный в админке или единственный `*.gguf` | managed: файл модели, выбор в админке отключается (в compose передаётся только профилю `server-only`) |
| `COSYVOICE_API_KEY` | — | ключ, если сервер запущен с `--api-key` |
| `COSYVOICE_VOICES` | `/voices` | external: папка голосов на машине сервера, куда сохраняются голоса из записи |
| `PORT` | `8080` | Docker: порт сервера на хосте |
| `TWITCH_CLIENT_ID` | — | можно задать и в интерфейсе |

## Отдельный домашний сервер

Основная схема: cosyvoice и `stream-tts` на сервере, на ПК стримера только OBS с
Browser Source `http://<сервер>:8090/overlay`. Оверлей открыт без пароля, он только читает. Админка (настройки,
токены) закрыта паролем. Обратная схема (синтез на сервере, `stream-tts` на ПК стримера) работает через
`COSYVOICE_URL` и `COSYVOICE_API_KEY`.
