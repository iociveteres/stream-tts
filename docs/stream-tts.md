# Stream TTS: озвучка наград Twitch голосами cosyvoice-server

Спецификация, согласовано 16.10.2026. Реализация: `stream-tts/` (описание запуска в README, раздел «Озвучка наград Twitch»).

## Что это

Сервис рядом с cosyvoice-server. Зритель активирует награду за баллы канала, вводит текст, и тот звучит на стриме
его голосом (как в JeetBot TTS). Голос зритель выбирает командой в чате. Захостить сервис может любой стример
у себя: он регистрирует своё приложение Twitch и входит своим аккаунтом.

Только Twitch. YouTube, VK Play и донаты не входят в скоуп.

## Сценарии

**Зритель**
- `!ttssf <голос>` в чате: выбрать свой голос. Имя голоса полное, как в `voices/` (`dota2-pudge`, `wc3-arthas`),
  без учёта регистра. Неизвестный или выключенный голос молча игнорируется. Ответов в чат и уведомлений нет.
- Активирует награду, вводит текст: текст звучит его голосом в порядке очереди.
- Если голос не выбран, при первой активации он назначается по хешу ника среди включённых голосов и сохраняется.
  Если выбранный голос потом выключат, зритель так же получает новый голос по хешу.
- Где посмотреть голоса: по ссылке, которую стример даёт сам (команда, панель). Сервис генерирует страницу со
  списком включённых голосов и примером звучания каждого. Голоса сгруппированы по наборам `voice-refs/<набор>/`
  (Warcraft III, игры, стримеры), голоса без образца в `voice-refs` — в «Другие».

**Модер и стример** (по бейджам в сообщении чата):

| Команда | Действие |
|---|---|
| `!ttsskip` | прервать текущую фразу (и её синтез), вернуть баллы |
| `!ttsclear` | очистить очередь, вернуть баллы за всё в ней |
| `!ttsban <ник>` / `!ttsunban <ник>` | запретить или разрешить зрителю озвучку |
| `!ttson` / `!ttsoff` | включить или выключить озвучку |

Модеры не могут менять голос другим зрителям.

**Стример** (веб-интерфейс): вход в Twitch, создание награды, настройки, голоса, очередь, статистика.

## Twitch

**Приложение Twitch.** Каждый хостящий регистрирует своё приложение на dev.twitch.tv. Общего Client ID в проекте
нет: иначе все инсталляции зависят от одного приложения и делят его лимиты. Интерфейс ведёт по шагам и проверяет
каждый:
1. Включить двухфакторную аутентификацию в аккаунте Twitch (без неё консоль разработчика не пустит). Ссылка на
   настройки безопасности.
2. Открыть консоль, «Register Your Application» (в новой вкладке: dev.twitch.tv в iframe не открывается).
3. Что вписать: имя (должно быть уникальным во всём Twitch, гайд предлагает `<канал>-stream-tts`), OAuth Redirect
   URL `http://localhost` (поле обязательное, но для входа по коду не используется), категория, **Client Type:
   Public**. Тип клиента после создания, вероятно, поменять нельзя, поэтому гайд выделяет этот пункт.
4. Скопировать Client ID и вставить в поле. Сервис сразу пробует начать вход и сообщает, если ID неверный.

У каждого шага описание и иллюстрация того, где что нажать. Client ID хранится в `/data`, можно задать и через
`.env` (`TWITCH_CLIENT_ID`).

**Вход.** Device Code Flow: интерфейс показывает код и ссылку twitch.tv/activate, стример входит своим аккаунтом
с любого устройства. Канал берётся из токена. Токен обновляется сам. Если refresh-токен истёк (у публичных клиентов
он, насколько известно, живёт около 30 дней), интерфейс просит войти заново, а награда ставится на паузу.

Scope: `channel:manage:redemptions` (создать награду, ставить на паузу, менять статус активаций и получать их),
`user:read:chat` (сообщения чата для команд).

**События.** EventSub WebSocket, публичный адрес не нужен:
- `channel.channel_points_custom_reward_redemption.add` с фильтром по ID нашей награды;
- `channel.chat.message` для команд.

Переподключение по `session_reconnect` и по пропаже keepalive, после него подписки создаются заново.

**Награда.** Создаёт сервис кнопкой в интерфейсе (`is_user_input_required`). Название, цена и кулдаун задаются
там же. Только у награды, созданной своим Client ID, можно менять статус активации, поэтому:
- сыгранная фраза отмечается `FULFILLED`;
- возврат баллов (`CANCELED`): текст пуст после фильтров, зритель в бане или не проходит по уровню доступа, очередь
  переполнена, синтез завершился ошибкой, `!ttsskip`, `!ttsclear`;
- озвучка выключена — награда на паузе (`is_paused`). Так «выкл» значит: не играть, не копить и не брать баллы;
- при остановке сервиса награда ставится на паузу, при старте снимается. Активации, оставшиеся `UNFULFILLED` после
  падения, при старте возвращаются.

Текст награды Twitch ограничивает сам (проверить, насколько: вероятно, 200 символов). Наш предел — 500 символов.

## Обработка активации

1. Проверки: озвучка включена, зритель не в бане, проходит по уровню доступа (все / сабы / VIP / модеры; Twitch к
   наградам такого ограничения не применяет). Иначе возврат.
2. Фильтры, каждый включается галочкой:
   - **ссылки** вырезаются: `http(s)://…`, `www.…`, `слово.домен` с известными доменами верхнего уровня;
   - **мат** запикивается: слово вырезается, фраза синтезируется кусками, а на месте слова звучит тон 800 Гц
     на ~9 дБ тише речи, с паузами 40 мс по краям. Слово «пип» голосом отвергнуто на слух (16.10.2026):
     звучало слишком громко и сливалось со словами. Поиск по корням (хуй, пизд, еб/ёб, бля, муд, пидор,
     залуп…) с учётом латиницы-двойников (`xуй`, `пuзда`) и разделителей (`х.у.й`). Список корней лежит в
     файле, его можно править. В субтитрах на месте мата `***`.

   Эмоуты читаются как текст. Если после фильтров текста не осталось, возврат.
3. Если включено чтение ника, перед текстом добавляется «<ник> говорит:».
4. В очередь. Лимит очереди задаётся в настройках, при переполнении возврат.

## Синтез и воспроизведение

- К cosyvoice-server идёт **строго один запрос за раз**. Следующая фраза синтезируется, пока играет текущая.
- `POST /tts`: `mode: zero-shot`, `voice`, `response_format: wav`. Длину ограничивают `max_token_text_ratio` и
  жёсткая обрезка: не больше 1,8× расчётной длины фразы (12 символов в секунду) и не больше 60 с.
- **Стриминг** (`"stream": true`, куски PCM16) включается галочкой, по умолчанию включён. Работает только для
  фраз длиннее полутора кусков (`chunk_tokens`, по умолчанию 150 токенов = 6 с звука, порог ~108 символов): у
  коротких первый звук пришёл бы почти одновременно с последним, а целиком синтез быстрее. `chunk_tokens`
  передаётся в каждом запросе, потому что сервер запоминает прошлое значение. Умолчание cosyvoice.cpp (28 токенов)
  синтезирует медленнее реального времени. На длинной фразе при 150 токенах первый звук приходит через ~2 с
  вместо 5–6 с, синтез идёт в ~2,5 раза быстрее реального времени. Голоса с `post` всегда синтезируются целиком.
  На CPU синтез медленнее реального времени, и стриминг там будет заикаться: интерфейс об этом предупреждает.
- `!ttsskip` во время синтеза вызывает `POST /tts/stop` (работает, когда сервер запущен с `--webui`, как сейчас).
- **Эффект `post`.** Если у голоса в `voice-refs/<набор>/manifest.json` (или в `manifest.json` установленного
  набора, `<голоса>/<набор>/manifest.json`) есть `post` (`[скрипт, аргументы…]`, путь к скрипту от корня проекта,
  например `effects/villager-fx.py`; `{text}` подставляется), он применяется к синтезу. Скрипт грузится через
  importlib в процессе stream-tts, вызывается его `apply(звук, аргументы)`; звук до и после проходит через PCM16, как
  раньше через WAV-файлы, поэтому результат совпадает с запуском из командной строки в `tools/voices/synth.py`
  ([voice-pipeline.md](voice-pipeline.md)) побайтно. Скрипт ищется в проекте, потом в поставке программы. Сейчас
  `post` не задан ни у одного голоса.
- **Громкость.**
  - Без стриминга: громкость фразы меряется по BS.1770 (LUFS), фраза доводится до −16 LUFS с ограничением пиков.
  - Со стримингом: у каждого голоса есть усиление, откалиброванное заранее по тестовой фразе.
  - В обоих случаях у голоса есть ручная поправка ±дБ.
- **Оверлей** `/overlay` — Browser Source в OBS. Он же работает в обычной вкладке: там нужен один клик «Включить
  звук» (так браузер разрешает автовоспроизведение). Звук идёт по WebSocket и играется через Web Audio. Играет
  только последний подключившийся оверлей, остальные показывают «неактивен». Субтитр «ник: текст» — опция.

## Голоса

Список берётся из `GET /speaker` сервера, туда входят все голоса (сейчас 69, с `wc3-*`). Каждый включается и
выключается галочкой, по умолчанию включены все. У каждого голоса есть поправка громкости и кнопка «послушать».
Алиасов нет.

**Страница для зрителей** — статический HTML (`/voices`, плюс выгрузка zip для хостинга, сам хостинг вне скоупа).
В ней включённые голоса, `!ttssf <имя>` для копирования и пример звучания каждого (mp3 демо-фразы, ~3–5 МБ на все).
Примеры кешируются и досинтезируются, когда набор голосов меняется.

## Статистика

Каждая активация пишется в SQLite: время, зритель, голос, длина текста, исход (сыграно, возврат и причина), время
ожидания, время синтеза, длина аудио. История хранится 30 дней.

Страница статистики:
- **сейчас** (сервер шлёт по WebSocket раз в 2 с): очередь, что играет, доступность cosyvoice, загрузка GPU;
- **за период**: активации по часам, топ голосов и зрителей, отказы по причинам, среднее ожидание до звука,
  отношение времени синтеза к длине аудио.

Загрузку GPU (`nvidia-smi`: загрузка, память, температура) сервис видит, только если стоит на одной машине с
видеокартой и ему проброшен GPU в `docker-compose.gpu.yml`. Иначе на странице «нет данных».

## Развёртывание

Два режима работы с cosyvoice-server, ядро одно:
- **external** — задан `COSYVOICE_URL`: сервер запущен отдельно (Docker, другая машина). Так работает
  `docker-compose.yml`.
- **managed** — `COSYVOICE_URL` не задан, а рядом есть нативный `cosyvoice-server(.exe)` (папка `runtime/` рядом с
  программой, в исходниках — в корне проекта, или путь в `COSYVOICE_SERVER`). stream-tts сам запускает его на
  `127.0.0.1` (свободный порт или `COSYVOICE_PORT`), перезапускает при падении и завершает при выходе (на Windows
  через Job Object, даже если stream-tts убит). Аргументы — как в `cosyvoice/entrypoint.sh` (`runtime.py`): модель
  (`MODEL` или единственный `*.gguf` в папке моделей; без модели сервер ждёт её появления), голоса `*.gguf` из папки
  голосов и её подпапок-наборов (имя голоса — имя файла), ONNX-фронтенд из `<модели>/frontend-onnx`, проверка AVX2.
  Бэкенд выбирается по `cosyvoice-cli --list-backends`: CUDA, если есть `ggml-cuda.dll` и видеокарта NVIDIA, иначе
  Vulkan (дискретная раньше встроенной), иначе CPU; `COSYVOICE_BACKEND=cuda|vulkan|cpu` задаёт его явно. Всегда
  `GGML_CUDA_DISABLE_GRAPHS=1`, на CUDA ещё `--llm-flash-attn 0`. В админке рядом с адресом сервера видны
  «встроенный», бэкенд, модель и число голосов.

**Первый запуск (режим managed)** — вкладка «Сервер» в админке (`install.py`), без модели админка открывается
сразу на ней:
- **Модель.** Карточки квантов Q8_0 (по умолчанию), Q6_K и Q5_K_M (`QUANTS` в `install.py`): размер файла,
  видеопамять, пояснение и примеры звука — одна фраза женским и мужским голосом (`static/quants/<голос>-<квант>.mp3`,
  синтез с seed 42). Видеопамять — пик cosyvoice-server на CUDA, RTX 3060 Ti, 2026-10-17: обычно / на самом длинном
  образце (***, 21,7 с) — Q8_0 ≈1,5 / 1,9 ГБ, Q6_K ≈1,45 / 1,8 ГБ, Q5_K_M ≈1,3 / 1,7 ГБ; на Vulkan пик примерно
  на 0,5 ГБ больше. На 54 фразах (6 голосов × 3 фразы × 3 seed) расшифровка Whisper (cer 0,011–0,017) и сходство
  CAM++ (0,810–0,820) у трёх квантов в пределах шума. Остальные кванты — `scripts/download-model.sh`; положенный
  вручную `*.gguf` тоже виден в списке и выбирается кнопкой «Использовать». Загрузка — как в
  `scripts/download-model.sh`: файл с Hugging Face пишется в `<имя>.part` с докачкой по Range и пятью повторами,
  сверяется с sha256 из заголовка `x-linked-etag` и только потом переименовывается. Прогресс, скорость и остаток
  времени видны в админке; «Отменить» оставляет `.part`, следующее «Скачать» продолжает с того же места. ONNX-фронтенд
  int8 — по галочке: для озвучки он не нужен. После загрузки модель выбирается (`settings.model`) и сервер
  запускается сам. Из нескольких установленных моделей используется выбранная. Квант, выбранный в установщике
  (`setup-model.txt` в папке программы), качается сам при первом запуске без модели — один раз
  (`settings.setup_download`), отмена его не перезапускает.
- **Устройство синтеза**: «Автоматически», CUDA, Vulkan или процессор (`settings.backend`); варианты, которых нет на
  машине, недоступны. Смена перезапускает сервер. `COSYVOICE_BACKEND` и `MODEL` выбор в админке перекрывают.
- **Наборы голосов** — zip с `*.gguf` и `manifest.json` (ключи — имена голосов: `title`, `post`…) в корне архива
  или в одной папке. Имя набора — эта папка или имя zip (латиница, цифры, `-`, `_`), оно же группа на странице
  голосов. Набор ставится в `<голоса>/<набор>/` целиком, повторная установка заменяет его, «✕» удаляет. Голос с
  именем, которое уже есть в другом наборе, пропускается; файлы не на верхнем уровне и не `.gguf` игнорируются,
  `.gguf` проверяется по сигнатуре. Пока файлы меняются, сервер остановлен (на Windows он держит `.gguf` открытыми),
  затем запускается с новым списком; stream-tts перечитывает голоса после каждого запуска сервера, примеры новых
  голосов синтезируются в фоне. `post` из `manifest.json` может ссылаться только на `effects/*.py`. Zip грузится
  сырым телом (`Content-Type: application/zip`, имя в `X-Filename`): такой запрос с чужой страницы требует
  CORS-проверки, как и JSON.

Рантайм для Windows (проверено 17.10.2026 на RTX 3060 Ti): cosyvoice.cpp v0.2.0
(`cosyvoice-67d45fe-windows-x64-ffmpeg.zip`), GGML из llama.cpp b11500 (`ggml*.dll` со всеми `ggml-cpu-*.dll`,
`libomp.dll`; `ggml-cuda.dll` с `cublas64_13`, `cublasLt64_13`, `cudart64_13` из `cudart-llama-bin-win-cuda-13.4-x64`;
`ggml-vulkan.dll`), ICU 78 (`icudt78`, `icuuc78`, `icuin78`), FFmpeg 8.1 lgpl-shared (DLL и `ffmpeg.exe`), VC++
2015–2022. Ядро без бэкендов GPU — 188 МБ, CUDA — ещё 664 МБ, Vulkan — 45 МБ. Скорость (RTF, фраза целиком):
CUDA 0,22–0,32, Vulkan 0,22–0,38 (первый запрос на новой машине ~35 с — компиляция шейдеров, кэш драйвера живёт
между запусками), CPU 4–9.

Пути (`paths.py`). Из исходников проекта — как раньше: `stream-tts-data/`, `models/`, `voices/`, `voice-refs/`,
`runtime/` в корне. Собранная программа хранит данные, модели и голоса в `%LOCALAPPDATA%\StreamTTS\` (Linux:
`$XDG_DATA_HOME/stream-tts`), код и статику только читает. Всё переопределяется переменными `STREAM_TTS_DATA`,
`STREAM_TTS_MODELS`, `STREAM_TTS_VOICES`, `STREAM_TTS_PROJECT`, `STREAM_TTS_RUNTIME`. ffmpeg ищется в рантайме и
рядом с программой, потом в `PATH` (или `FFMPEG`).

**Docker.** Второй сервис `stream-tts` в `docker-compose.yml`, стартует параллельно cosyvoice, `restart: unless-stopped`.

- Образ: `python:3.15-slim` (аргумент `PYTHON` в `stream-tts/Dockerfile`; если колёс под новую версию нет —
  вернуть 3.14), ffmpeg, aiohttp, numpy.
- Тома: `./stream-tts-data:/data` (SQLite, настройки, токены, кеш примеров), `voice-refs/` и `effects/` (скрипты
  эффектов) только для чтения. Режим `cut` в `effects/villager-fx.py` звуки жителя не читает. Остальным режимам нужна
  `voice-origs/minecraft-villager/`.
- cosyvoice доступен по docker-сети (`http://cosyvoice:8080`), его порт остаётся на `127.0.0.1`.

Переменные `.env` (в программе для Windows — `stream-tts.env`, см. «Сборка для Windows»):

| Переменная | По умолчанию | Зачем |
|---|---|---|
| `STREAM_TTS_PORT` | `8090` | порт интерфейса и оверлея |
| `STREAM_TTS_BIND` | `127.0.0.1` | `0.0.0.0`, чтобы OBS на другом ПК дотянулся по сети |
| `STREAM_TTS_PASSWORD` | — | пароль админки; обязателен, если `BIND` не localhost |
| `COSYVOICE_URL` | `http://cosyvoice:8080` в compose | внешний сервер; без него — режим managed |
| `COSYVOICE_SERVER` | `runtime/cosyvoice-server(.exe)` | managed: путь к серверу или его папке |
| `COSYVOICE_BACKEND` | `auto` | managed: `cuda`, `vulkan` или `cpu` |
| `COSYVOICE_PORT` | свободный | managed: порт сервера на `127.0.0.1` |
| `MODEL` | единственный `*.gguf` | managed: файл модели |
| `COSYVOICE_API_KEY` | — | ключ, если сервер запущен с `--api-key` |
| `TWITCH_CLIENT_ID` | — | можно задать и в интерфейсе |

### Сборка для Windows

Программа без Docker и Python: Setup.exe ставит StreamTTS в Program Files, данные, модель и голоса живут в
`%LOCALAPPDATA%\StreamTTS\` и при удалении остаются. Модели в установщике нет: на странице «Модель синтеза»
выбирается квант (те же три, что во вкладке «Сервер», с размером, видеопамятью и кнопками «Женский голос»,
«Мужской голос», «Стоп» — mp3 из `static/quants/` через MCI), выбор пишется в `{app}\setup-model.txt`, и программа
качает модель сама при первом запуске, админка открывается на вкладке «Сервер». Если в
`%LOCALAPPDATA%\StreamTTS\models\` модель уже есть (обновление), страница пропускается; при тихой установке
берётся Q8_0 или выбор прошлой установки. Файлы — в `packaging/windows/`:

- `build-runtime.py` — рантайм с закреплёнными версиями и sha256 (см. выше): `build/runtime/core/` (279 МБ),
  `build/runtime/cuda/` (664 МБ), `vc_redist.x64.exe`. Нужна только стандартная библиотека Python.
- `build-exe.py` — `StreamTTS.exe` через Nuitka (standalone, консольное приложение) в `dist/StreamTTS/` (73 МБ):
  пакет `streamtts` со `static/` и `profanity.txt`, `effects/villager-fx.py`. Нужен сборочный venv
  (`requirements.txt`: зависимости stream-tts и Nuitka) на Python 3.14 и MSVC (Visual Studio или Build Tools с C++):
  MinGW Nuitka для Python 3.13+ не поддерживает. Первая сборка ~6 мин, повторные быстрее за счёт кэша компилятора.
  `--runtime core|all` кладёт рантайм рядом с exe для запуска без установщика, `--setup` собирает установщик.
- `StreamTTS.iss` — Inno Setup 6: `dist/StreamTTS-Setup-<версия>.exe`. Компоненты: основной (программа, рантайм
  без CUDA) и CUDA; CUDA по умолчанию снята, если в системе нет `nvcuda.dll` (драйвера NVIDIA). VC++ Redistributable
  ставится тихо, если в реестре (`HKLM\SOFTWARE\Microsoft\VisualStudio\14.0\VC\Runtimes\x64`) версия старше 14.51:
  cosyvoice собран тулсетом 14.51 и со старым рантаймом не запускается. Запущенную программу установщик видит по
  мьютексу `StreamTTS` и просит закрыть. Установщик со всеми компонентами — 611 МБ, сжатие ~1 мин (проверено на
  Inno Setup 6.7.3). Inno Setup можно не ставить в систему: `innosetup-6.x.exe /PORTABLE=1 /CURRENTUSER /VERYSILENT
  /DIR=<папка>` и путь к `ISCC.exe` в переменной `ISCC`.
- `.github/workflows/windows.yml` — то же в GitHub Actions (`windows-latest`, по кнопке или тегу `v*`), установщик —
  артефакт сборки.

```bash
packaging/windows/.venv/Scripts/python.exe packaging/windows/build-runtime.py
packaging/windows/.venv/Scripts/python.exe packaging/windows/build-exe.py --runtime core --setup
```

Запуск (`desktop.py`, работает и из исходников: `python -m streamtts.desktop`):
- переменные из таблицы выше читаются ещё и из `%LOCALAPPDATA%\StreamTTS\stream-tts.env` (`KEY=VALUE`, переменные
  окружения важнее); при первом запуске там появляется пример с комментариями;
- одна копия на папку данных: повторный запуск открывает админку уже запущенной и выходит;
- админка открывается в браузере, когда сервер ответил (`--no-browser` — не открывать);
- лог — в консоли и в `%LOCALAPPDATA%\StreamTTS\logs\stream-tts.log` (три старых файла по 2 МБ);
- закрыть окно консоли — выключить stream-tts, встроенный cosyvoice-server завершается вместе с ним. Если запуск
  не удался (порт занят), окно ждёт Enter, чтобы ошибку можно было прочитать.

Эффект `villager-fx.py` в программе работает только в режиме `cut`: звуков жителя из `voice-origs/` в поставке нет.

**Отдельный домашний сервер.** Основная схема: cosyvoice и `stream-tts` на сервере, на ПК стримера только OBS с
Browser Source `http://<сервер>:8090/overlay`. Оверлей открыт без пароля, он только читает. Админка (настройки,
токены) закрыта паролем. Обратная схема (синтез на сервере, `stream-tts` на ПК стримера) работает через
`COSYVOICE_URL` и `COSYVOICE_API_KEY`.
