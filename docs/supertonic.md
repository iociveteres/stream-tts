# Supertonic 3 — третья модель

Supertonic 3 (Supertone, ONNX, ~99M параметров, 31 язык, в том числе русский) — лёгкая модель синтеза только на
процессоре: видеокарта остаётся игре и стриму, памяти — около 0,5 ГБ. Своего клонирования голоса у модели нет
(Voice Builder авторов закрыт, репозиторий кода в архиве): только 10 готовых голосов — M1–M5 (мужские), F1–F5
(женские). stream-tts запускает её сервер, supertonic-server (`supertonic/`), так же, как cosyvoice-server и
espeech-server, и говорит с ним по общему протоколу (`stream-tts/streamtts/engines/client.py`).

Как устроен синтез (`supertonic/model.py`, перенос `py/helper.py` официального репозитория): текст → индексы символов
Юникода (`unicode_indexer.json`, после NFKD: «й» и «ё» — буква и надстрочный знак) с тегами языка `<ru>…</ru>` →
`duration_predictor` (длительность фразы в секундах, делится на `speed`) → `text_encoder` → `vector_estimator`
(flow matching: `total_step` шагов из гауссова шума латента; шум — из генератора с `seed`) → `vocoder` (44,1 кГц).
Длинный текст режется на куски до 300 символов по предложениям (`chunk_text`), между кусками — пауза 0,3 с. Звук
обрезается по предсказанной длительности и пересчитывается в 24 кГц.

## supertonic-server

Пакет `supertonic/` в корне проекта: `server.py` (HTTP API, запуск), `model.py` (синтез), `voices.py` (папка
голосов), `text.py` (подготовка текста), `THIRD-PARTY.txt` (MIT кода авторов). Зависимости — только стандартная
библиотека, numpy 2.5.4 и onnxruntime 1.31.0 (CPUExecutionProvider) — те же версии, что в
`stream-tts/requirements.txt`, отдельное окружение не нужно. Нормализатор русского текста — из `espeech/` (импорт
не тянет torch и RUAccent), поэтому запуск — из корня проекта (или с корнем в `sys.path`):

```bash
stream-tts/.venv/Scripts/python -m supertonic --models models/supertonic --voices voices --port 8096
```

| Аргумент | По умолчанию | Что |
|---|---|---|
| `--models` | (обязателен) | папка модели в раскладке HF; без файлов — сообщение в stderr со списком недостающих и выход с кодом 2 |
| `--voices` | — | папка голосов: `<имя>.supertonic` и `<набор>/<имя>.supertonic` |
| `--host`, `--port` | 127.0.0.1, 8096 | адрес |
| `--threads` | 4 | потоков onnxruntime на сессию; 0 — по числу ядер (замер ниже: больше 2–4 почти не ускоряет) |
| `--steps`, `--speed` | 8, 1.05 | значения для запроса без `total_step` и `speed` |
| `--log-level` | INFO | на каждую фразу — строка: голос, символов, секунд звука, время синтеза |

Модель грузится в фоне за ~1,7 с: до этого `/status` отвечает `model_loaded: false`, `/tts` — 503. Если файлы на
месте, но не читаются, сервер пишет ошибку в stderr и выходит с кодом 1.

### Голоса

Голос — файл `<имя>.supertonic`: JSON стиля из `voice_styles/*.json` модели как есть (`style_ttl` [1, 50, 256] и
`style_dp` [1, 8, 16], у каждого `dims` и `data`). Имя голоса — имя файла; файлы ищутся в `--voices` и на один
уровень подпапок (наборы), папка перечитывается при каждом запросе. Одно имя в двух наборах — берётся первый
(корень, затем наборы по алфавиту). Готовые голоса stream-tts ставит набором `supertonic` под понятными зрителю
именами (`voices/supertonic/anna.supertonic` …, «Поставка»).

### API

Подмножество API cosyvoice-server, как у espeech-server; ошибки — текстом по-русски.

- `GET /status` → `{engine: "supertonic", api_version: 1, model: "Supertonic 3", model_loaded, device: "cpu",
  capabilities: {stream: true, extract: false, accent: false, train: false, voice_formats: ["supertonic"]},
  params}`; `params` — схема настроек для админки: `total_step` (choice 5 / 8 / 12 / 16, по умолчанию 8, «Качество
  синтеза»), `speed` (choice 0.9 / 1.0 / 1.05 / 1.15 / 1.3, по умолчанию 1.05, «Скорость речи»); `title` и `help`
  по-русски — переводит stream-tts. Отвечает и во время синтеза.
- `GET /speaker` → список имён голосов.
- `DELETE /speaker/<имя>` → 200 — забыть голос (файл не трогается; голос вернётся, когда файл изменится, или после
  перезапуска), 404 — нет такого.
- `POST /speaker?type=extract`, `POST /speaker/save` → 501 `{error: "unsupported", message}`.
- Запрос с заголовком `Origin` (из браузера) — 403, тело JSON без `Content-Type: application/json` — 415
  (`espeech.wire.refuse_browser`, `require_json`; как у espeech-server).
- `POST /tts` JSON `{text, voice, stream?: false, seed?: int ≥ 0, total_step?: int, speed?: float, lang?: "ru"}` →
  200 `audio/wav`, PCM16 моно 24000 Гц. `stream: true` — `Transfer-Encoding: chunked`: сначала WAV-заголовок с
  неизвестной длиной (`0xFFFFFFFF`, как у cosyvoice-server), затем PCM каждого куска по мере синтеза; в потоке
  первое предложение — отдельным куском (первый звук раньше, см. замеры). `total_step` — 1…32, `speed` — 0,5…2 (вне
  `choices` можно для замеров), `lang` — один из 31 языка модели. 404 — нет голоса, 400 — неверные параметры, 500 —
  файл голоса не читается. Поля cosyvoice (`mode`, `chunk_tokens`, …) игнорируются. Текст, пустой после
  нормализации (одни эмодзи), — 0,1 с тишины.
- `POST /tts/stop` → 200: текущий синтез останавливается перед ближайшим шагом модели или куском (десятки мс). Ответ
  без потока — то, что успело синтезироваться (или 0,1 с тишины), поток — завершается. Следующий запрос стоп не
  задевает.

Синтез строго один за раз (блокировка): второй `/tts` ждёт первый, а `/status`, `/speaker` и `/tts/stop` отвечают
сразу — каждый запрос в своём потоке `ThreadingHTTPServer`. HTTP/1.1 keep-alive: простаивающее соединение сервер
держит 60 с (stream-tts — не дольше 2 с, `KEEPALIVE`). Клиент отключился посреди потока — синтез бросается на
следующем куске.

### Текст

`text.py`: знаки ударения «+» перед гласной (разметка «з+амок» для ESpeech) убираются (`espeech.accent.unmark`),
русский (`lang: "ru"`) проходит нормализатор espeech-server `espeech/normalize.py` — числа с падежом и родом, время,
даты, счёт, деньги и единицы, латиница и ники («xXx_Killer_2007» → «киллер две тысячи семь», «gg» → «гэгэ»),
сленг чата, смайлы и эмодзи (подробно — docstring модуля и docs/espeech.md). Он чистый Python (re, unicodedata,
свои числительные), из `espeech/` берутся только `normalize`, `numbers`, `numerals`, `latin`, `accent.unmark` и
`wire` (заголовок WAV, PCM16), `espeech/__init__.py` лишь подключает папки `ESPEECH_DLL_DIRS`, если они заданы;
`espeech/` для этого не менялся. Словаря словоформ RUAccent у supertonic-server нет: транслит латиницы проверяется
только по встроенному списку частых слов. Другие языки идут как есть. Дальше — подготовка текста авторов
(`model.preprocess`): NFKD, тире и кавычки, точка в конце; символ, которого нет в `unicode_indexer.json`,
выбрасывается.

### Звук: 44,1 → 24 кГц

Пересчёт частоты — свой, через БПФ (`model.resample`, numpy): спектр обрезается на 12 кГц со спадом косинусом в
верхних 5 %. `resample` из `stream-tts/streamtts/audio.py` не подходит: это линейная интерполяция без фильтра — при
понижении частоты 12–22 кГц заворачиваются в слышимую полосу (тон 15 кГц становится 9 кГц; `test_text.py` это
ловит), а импортировать пакет stream-tts сервер не должен (сервер — отдельный процесс со своими зависимостями).

## Замеры

Ryzen 5 5600G (6 ядер, 12 потоков), Windows 10, onnxruntime 1.31.0 CPU, голос M1, через HTTP с `stream: true`,
медиана трёх запусков. «Первый звук» — от запроса до первого PCM в потоке, RTF — время синтеза / длительность
звука.

Фразы: награда, 82 символа, 8 с звука («Спасибо за подписку, Killer2007! Сегодня проходим кампанию нежити до самого
конца.»), и объявление, 308 символов (5 предложений, числа и латиница), 23 с звука. Сервер как по умолчанию
(4 потока, без арены памяти onnxruntime):

| Шагов | 82 симв.: первый звук | целиком | RTF | 308 симв.: первый звук | целиком | RTF |
|---|---|---|---|---|---|---|
| 5 | 0,61 с | 1,26 с | 0,16 | 0,32 с | 3,9 с | 0,17 |
| 8 | 0,90 с | 1,84 с | 0,23 | 0,48 с | 5,8 с | 0,25 |
| 12 | 1,36 с | 2,78 с | 0,35 | 0,72 с | 8,4 с | 0,37 |

Первый звук — первое предложение отдельным куском; без этого он пришёл бы только с «целиком» (фраза до 300
символов — один кусок). Дальше каждый кусок готов быстрее, чем играет предыдущий (RTF ≤ 0,37): звук идёт без пауз
ожидания. 16 шагов — примерно на треть дольше 12.

Потоки (`--threads`, 8 шагов, с ареной памяти — она быстрее на ~6 % на короткой фразе и на 15–18 % на длинной):

| Потоков | 1 | 2 | 4 | 6 | 12 |
|---|---|---|---|---|---|
| 82 симв. целиком | 3,12 с | 1,91 с | 1,85 с | 1,94 с | 1,93 с |
| 308 симв. целиком | 9,2 с | 5,2 с | 4,9 с | 4,8 с | 4,8 с |

Больше 4 потоков не быстрее: остальные ядра остаются OBS и игре. Арена памяти выключена (`model.py`): с ней после
фразы в 300 символов процесс держит 600 МБ рабочего набора и 1,1 ГБ выделенной памяти (арена хранит пик самой
длинной фразы), без неё — 470 и 850 МБ; после загрузки модели — 460 МБ. Загрузка — 1,7 с.

Разборчивость: 14 примеров (`samples/supertonic/`) faster-whisper small распознал почти дословно; заметные огрехи —
«тысяча пятьсот» местами звучит как «тысяча пять», а ник с хвостом «xXx» нормализатор читает «икс икс икс»
(«Warcraft III» — «ай ай ай»: так `espeech/normalize.py` читает римские цифры как латиницу).

## Поставка

Везде одинаково — у программы для Windows, в Docker и из исходников: модель качает кнопка «Скачать» в карточке
Supertonic 3 на вкладке «Загрузки» (`stream-tts/streamtts/engines/supertonic/download.py`, очередь Installer в
`install.py`, `POST /api/download` и `/api/download/delete` с `id=supertonic` — через `_restart_guard`). Если модель
ещё не выбрана (первая загрузка), Supertonic 3 становится выбранной. Веса в установщик и образ не
кладутся (OpenRAIL-M, «Лицензии»): перед загрузкой админка показывает условия и ссылку на `LICENSE` закреплённой
ревизии и спрашивает согласие.

- **Что качается.** Раздел `supertonic` в `stream-tts/streamtts/downloads.json`: репозиторий, ревизия, адрес
  `https://huggingface.co/Supertone/supertonic-3/resolve/<ревизия>` и 17 файлов из таблицы выше с размером и
  sha256. Каждый — `fetch.py`: в `<файл>.part` с докачкой (Range) и повторами, сверка sha256, потом переименование;
  файл того же размера уже на месте — не качается. Папка — `<модели>/supertonic/` в раскладке HF (её и ждёт
  сервер), `LICENSE` — рядом с весами. Проверено: размеры всех файлов и sha256 весов совпадают с ответами Hugging
  Face (`x-linked-size`, `x-linked-etag`), малые файлы скачиваются с тем же sha256.
- **Готовые голоса.** После загрузки 10 стилей `voice_styles/*.json` копируются как есть в
  `<голоса>/supertonic/<имя>.supertonic`, в `manifest.json` набора — запись на голос (группа «Supertonic 3» на
  странице голосов, примеры синтезируются сами). Имена (`VOICES` в `download.py`): M1–M5 — `anton`, `boris`, `gleb`,
  `oleg`, `pavel`, F1–F5 — `anna`, `vera`, `nina`, `olga`, `rita`. Зритель выбирает голос командой `!ttssf <имя>`:
  «m1» ему ничего не говорит, а здесь пол слышен по имени, имена короткие, латиницей без двойного прочтения (нет ж,
  ш, й, х, ц) и по алфавиту в порядке номеров стиля. Пропал голос (удалили набор) — «Скачать» (метка «голосов: 9 из 10»)
  возвращает его без загрузки; голоса пользователя в той же папке не трогаются.
- **Запуск.** Сервер, ждущий модель (`runtime.Unavailable` «нет модели Supertonic 3»), после загрузки
  перезапускается и поднимается сам. Чем запускается — `engines/supertonic/launch.py`: программа для Windows —
  сама (`StreamTTS.exe --supertonic <аргументы>`: пакет `supertonic` и модули `espeech/` нормализатора
  скомпилированы в exe, `packaging/windows/build-exe.py`, `StreamTTS.py`; путь к exe — `paths.PROGRAM`, у Nuitka
  `sys.executable` — несуществующий `python.exe`); Docker — Python образа, код — `/opt/cosyvoice/supertonic/supertonic`
  и `/opt/cosyvoice/espeech/espeech` (`Dockerfile`) в `PYTHONPATH`; из исходников — интерпретатор stream-tts.
  Своего рантайма нет: numpy и onnxruntime у stream-tts те же.
- **Удаление** («✕» в карточке) — при остановленном сервере: папка модели и 10 готовых голосов с их записями в
  `manifest.json`; потом сервер снова ждёт модель.
- **Лицензии кода** — `supertonic/THIRD-PARTY.txt` (MIT кода Supertone): у программы — `licenses\supertonic-THIRD-PARTY.txt`
  и строка в `packaging/windows/THIRD-PARTY*.txt` (страница «Информация» установщика, там же — веса по кнопке), в
  образе — рядом с кодом сервера.

Проверено на собранной программе (порт 8098, свои данные, файлы модели — из `models/supertonic` разработчика через
локальный HTTP-сервер): загрузка 383 МБ, голоса и примеры всех 10, фраза 82 символа — 8,2 с звука за 1,9 с, процесс
сервера — 488 МБ рабочего набора, удаление. Раскладка образа — запуском сервера вне проекта только с двумя этими
папками в `PYTHONPATH`.

## Тесты

stream-tts: `tests/e2e/test_supertonic_download.py` — загрузка без сети (докачка, неверный sha256, голоса, запуск
сервера, удаление), закрепление в `downloads.json`, запуск у программы и в Docker, модули `espeech/` в сборке exe.

`stream-tts/.venv/Scripts/python -m pytest tests/supertonic` (~20 с, настоящая модель на процессоре; без модели
пропускаются; в worktree модель берётся из основной копии репозитория, путь можно задать `SUPERTONIC_MODELS`):

- `test_text.py` — без модели: нормализация и ударения, импорт без torch и RUAccent, подготовка текста авторов,
  нарезка на куски, пересчёт частоты без наложения спектров;
- `test_server.py` — сервер отдельным процессом: `/status` по контракту, голоса из `--voices` (наборы, DELETE,
  возврат после изменения файла, битый файл), 501, ошибки 400/404, WAV PCM16 моно 24 кГц, воспроизводимость `seed`,
  «+» не меняет звук, поток (заголовок, куски по мере синтеза), `/tts/stop`, один синтез за раз при отвечающем
  `/status`, keep-alive дольше 2 с, выход без модели.

Примеры на слух (все 10 голосов, числа, латиница, ники; шаги 5 / 8 / 12) — `samples/supertonic/` (вне git), тексты и
то, как их прочитал нормализатор, — `samples/supertonic/texts.txt`.
