# StreamTTS: озвучка наград Twitch локальным синтезом речи

Зритель активирует награду за баллы канала или пишет команду в чат, и текст звучит на стриме выбранным голосом.
Синтез идёт на вашем компьютере, без облачных сервисов:
- [CosyVoice3](https://huggingface.co/Lourdle/Fun-CosyVoice3-0.5B-2512-GGUF) через
  [cosyvoice.cpp](https://github.com/Lourdle/cosyvoice.cpp) — клонирование голоса по короткой записи, работает на
  CPU, а на видеокарте NVIDIA примерно в 15 раз быстрее;
- [ESpeech](#вторая-модель-espeech) (F5-TTS) — естественнее звучит, нужна видеокарта, умеет дообучаться (LoRA);
- [Supertonic 3](#третья-модель-supertonic-3) — лёгкая модель на процессоре с 10 готовыми голосами.

Всё настраивается в админке в браузере: Twitch, очередь, голоса, загрузка моделей. Модели в программу и образ не
входят, админка качает их по кнопкам.

## Установка

Два способа:
- **Программа для Windows** — установщик без Docker и Python.
- **Docker** — Linux или Windows с Docker Desktop: готовый образ, две команды. Подходит и для отдельного сервера,
  к админке которого ходят по локальной сети.

### Программа для Windows

Скачайте `StreamTTS-Setup-<версия>.exe` со страницы
[Releases](https://github.com/iociveteres/stream-tts/releases) и запустите. Права администратора не нужны, всё
хранится в папке программы. После установки откроется админка: на вкладке «Загрузки» скачайте модель (и CUDA, если
есть видеокарта NVIDIA). Подробнее: [docs/stream-tts-windows.md](docs/stream-tts-windows.md).

### Docker: требования

| | |
|---|---|
| Процессор | x86_64 с **AVX2** (Intel с 4-го поколения, AMD Zen и новее) |
| ОС | Linux или Windows 10/11 с Docker Desktop (бэкенд WSL2) |
| Docker | Docker Engine с Compose v2 (`docker compose`) |
| RAM | около 4 ГБ свободной памяти для Q8_0 |
| Диск | около 1,8 ГБ (образ 597 МБ, модель 944 МБ, фронтенд 250 МБ); с GPU ещё ~730 МБ CUDA (качается в админке) |
| GPU (необязательно) | NVIDIA с драйвером для CUDA 13 (R580+), 1,5–2 ГБ видеопамяти для Q8_0; Docker с доступом к GPU (Docker Desktop с WSL2 или NVIDIA Container Toolkit) |

macOS на Apple Silicon и ARM-Linux не поддерживаются: бинарники собраны под x86_64, а при эмуляции нет AVX2.

### Docker: установка

В пустой папке скачайте `docker-compose.yml` и запустите его. Образ (`ghcr.io/iociveteres/stream-tts`) Docker
скачает сам, папки для настроек, моделей и голосов создаст рядом с файлом.

```bash
curl -fsSLO https://raw.githubusercontent.com/iociveteres/stream-tts/main/docker-compose.yml
```

```bash
docker compose up -d
```

В PowerShell на Windows вместо `curl` пишите `curl.exe`: просто `curl` там — другая команда.

Откройте админку **http://localhost:8090** и на вкладке «Загрузки» скачайте модель. Дальше всё в ней: Twitch, очередь,
голоса (раздел [«Озвучка наград Twitch»](#озвучка-наград-twitch-stream-tts)).

**С видеокартой NVIDIA** скачайте ещё `docker-compose.gpu.yml` — он даёт контейнеру видеокарту:

```bash
curl -fsSL --remote-name-all https://raw.githubusercontent.com/iociveteres/stream-tts/main/docker-compose.yml https://raw.githubusercontent.com/iociveteres/stream-tts/main/docker-compose.gpu.yml
```

```bash
docker compose -f docker-compose.yml -f docker-compose.gpu.yml up -d
```

Образ тот же, что без видеокарты: CUDA (~590 МБ загрузки) скачивается кнопкой на вкладке «Загрузки» (карточка
«Видеокарта NVIDIA») в папку `./cuda`. Чтобы не писать `-f` в каждой команде, положите рядом файл `.env` со строками
`COMPOSE_FILE=docker-compose.yml:docker-compose.gpu.yml` и `COMPOSE_PATH_SEPARATOR=:`.

Управление контейнером (из той же папки):

```bash
docker compose logs -f   # логи
docker compose down      # остановить
docker compose up -d     # запустить снова (модель — выбранная в админке)
```

Обновление до новой версии:

```bash
docker compose pull
```

```bash
docker compose up -d
```

Админка открыта в локальной сети: с другого ПК — `http://<адрес компьютера>:8090`, без пароля и настроек. Из
интернета (проброс порта, туннель, прокси) админка пускает только с паролем — он задаётся в админке: «Настройки» →
«Сервер». Забыли пароль — удалите `stream-tts-data/admin-password` и перезапустите контейнер. Только с этого
компьютера — `STREAM_TTS_BIND=127.0.0.1` в `.env`. Остальные переменные `.env` (порт, язык, Client ID) — в
[docs/stream-tts-deploy.md](docs/stream-tts-deploy.md#переменные).

### Docker из репозитория: `setup.sh`

Нужен для инструментов подготовки голосов (`scripts/`, `tools/`), выбора кванта модели при установке и сборки образа
из исходников. Команды выполняются в bash: Linux, WSL2 или Git Bash на Windows (см. [ниже](#windows)).

```bash
git clone https://github.com/iociveteres/stream-tts.git
```

```bash
cd stream-tts
```

```bash
./setup.sh
```

Скрипт выполняет пять шагов:
1. Проверяет, что Docker установлен и запущен.
2. Скачивает модель (по умолчанию `Q8_0`) и ONNX-фронтенд для клонирования в `./models`. Если файлы уже есть, пропускает их.
3. Записывает в `.env` порт и (с `--gpu` или `--build`) набор compose-файлов.
4. Скачивает готовый образ (с `--build` — собирает его из `Dockerfile`) и запускает контейнер stream-tts со
   встроенным cosyvoice-server.
5. Ждёт, пока сервер ответит, и выводит адреса, в том числе адрес для других ПК в локальной сети.

После этого WebUI сервера доступен по адресу **http://localhost:8080**, админка stream-tts — **http://localhost:8090**.

Параметры:

```bash
./setup.sh Q6_K                  # другой квант
./setup.sh Q8_0 --frontend full  # полный ONNX-фронтенд (~1 ГБ) вместо int8
./setup.sh Q8_0 --frontend none  # без фронтенда (клонирование из аудио будет недоступно)
PORT=9000 ./setup.sh             # другой порт сервера синтеза на хосте
./setup.sh Q8_0 --gpu            # на видеокарте NVIDIA (CUDA)
./setup.sh Q8_0 --build          # образ из исходников, эффекты и manifest.json голосов — из папок проекта
```

Скрипт прописывает в `.env` нужные compose-файлы (`COMPOSE_FILE`): с `--gpu` — `docker-compose.gpu.yml`, с `--build`
— `docker-compose.dev.yml`. Поэтому обычные `docker compose up/down/logs` дальше работают с тем же набором. Чтобы
вернуться на CPU или к готовому образу, запустите `./setup.sh` без этих флагов. После `git pull` с `--build` —
`docker compose up -d --build`.

Инструменты подготовки голосов (`scripts/`, `tools/`) работают с сервером внутри контейнера stream-tts — порт 8080,
отдельный сервис не нужен. Пока они работают, не заказывайте озвучку: сервер выполняет запросы строго по одному.

#### Windows

Docker Desktop должен быть запущен. Скрипт выполняется из Git Bash или из WSL2-дистрибутива, из PowerShell напрямую не запустится.
Если работаете в WSL, держите проект в домашней папке WSL (`~/...`), а не на `/mnt/c/...`: модель будет загружаться заметно быстрее.

## Модели

Список квантов с размерами:

```bash
scripts/download-model.sh --list
```

| Квант | Размер | Видеопамять (CUDA) | Комментарий автора модели |
|---|---|---|---|
| `Q8_0` | 944 МБ | ≈1,5 ГБ, до 1,9 | **по умолчанию**, почти без потерь |
| `Q6_K` | 840 МБ | ≈1,45 ГБ, до 1,8 | хорошее качество |
| `Q5_K_M` / `Q5_1` | ~683 МБ | ≈1,3 ГБ, до 1,7 | приемлемо |
| `Q4_K_M` | 629 МБ | — | иногда звук приглушённый |
| `Q3_*`, `Q2_*` | < 530 МБ | — | заметные артефакты |

Видеопамять — пик cosyvoice-server на RTX 3060 Ti: обычно и на самом длинном образце голоса (~22 с); на Vulkan
примерно на 0,5 ГБ больше. Q8_0, Q6_K и Q5_K_M мы сравнили на 54 фразах: разборчивость (Whisper) и сходство
голоса (CAM++) в пределах шума, разница на слух едва заметна
([docs/stream-tts-deploy.md](docs/stream-tts-deploy.md#первый-запуск)).

Если Hugging Face недоступен, файлы можно скачать вручную и положить так:

```
models/
├── CosyVoice3-2512_Q8_0.gguf
└── frontend-onnx/
    ├── campplus.int8.onnx            (или campplus.onnx)
    └── speech_tokenizer_v3.int8.onnx (или speech_tokenizer_v3.onnx)
```

Если в `models/` лежит несколько `.gguf`, нужная выбирается в админке stream-tts (вкладка «Сервер»).

## Использование

### Клонирование голоса (WebUI)

1. Откройте вкладку **Extract**.
2. Загрузите аудио (5–15 секунд чистой речи без музыки и шума) или запишите его с микрофона.
3. Введите **точную расшифровку** того, что сказано на записи, и задайте имя голоса.
4. Голос появится в списке спикеров, и им можно озвучивать любой текст.

Чтобы голос пережил перезапуск контейнера, сохраните его через **Save speaker** по пути `/voices/<имя>.gguf`.
Все файлы из `./voices` подключаются автоматически при старте под именами файлов, вместе с одним уровнем подпапок
(наборов): `voices/wc3/thrall.gguf` станет голосом `thrall`. Если два файла дают одно имя, подключается первый, а
второй пропускается с предупреждением в логе. В **Save speaker** можно указать путь в подпапке, например
`/voices/wc3/thrall.gguf`; саму подпапку создайте заранее.

### Режимы синтеза

| Режим | Что делает |
|---|---|
| **zero-shot** | Озвучивает текст голосом и в манере образца. Чтобы получить нужную интонацию, дайте образец, где она уже есть. |
| **instruct** | Тот же голос плюс текстовая инструкция к стилю («говори шёпотом, медленно»). Инструкции на английском или китайском, вероятно, работают надёжнее русских. |
| **cross-lingual** | Голос образца на другом языке. |

### HTTP API

Регистрация голоса из аудио:

```bash
curl -X POST "http://localhost:8080/speaker?type=extract" \
  -F name=myvoice \
  -F "text=Точная расшифровка записи." \
  -F "audio=@sample.wav"
```

Синтез:

```bash
curl -X POST http://localhost:8080/tts \
  -H 'Content-Type: application/json' \
  -d '{"text":"Привет!","voice":"myvoice","mode":"zero-shot","format":"wav"}' \
  -o out.wav
```

С инструкцией к стилю: `"mode":"instruct","instruction":"Speak in a slow, mysterious whisper."`.

Сохранение голоса на диск:

```bash
curl -X POST http://localhost:8080/speaker/save \
  -H 'Content-Type: application/json' \
  -d '{"name":"myvoice","path":"/voices/myvoice.gguf"}'
```

Состояние сервера: `GET /status`, `GET /speaker`, `GET /formats`. Полный справочник API есть в
[docs/TOOLS.md](https://github.com/Lourdle/cosyvoice.cpp/blob/v0.2.0/docs/TOOLS.md) проекта cosyvoice.cpp.
Учтите, что `POST /model/load` на самом деле ждёт поле `model`, а не `model_path`, как написано там.
Кроме того, после выгрузки модели все зарегистрированные голоса сбрасываются.

Форматы вывода — поле `format` (не `response_format`, как у OpenAI: его сервер молча пропускает и отдаёт
WAV): `wav`, `mp3`, `opus`, `flac`, `aac`, `m4a`, `pcm`.

### Голоса

Голосов CosyVoice3 и ESpeech в репозитории и установщике нет: их образцы — реплики из игр и чужие записи. Голос
делается из своей записи — «+ Добавить голос» на вкладке «Голоса», вкладка **Extract** в WebUI (выше) или
`scripts/import-voices.sh` (ниже). Готовую коллекцию (zip с файлами `.gguf` или `.espeech`) ставят на вкладке
«Голоса» → «Наборы голосов». У Supertonic 3 голоса готовые, они ставятся вместе с моделью.

Голоса, собранные автором проекта (Warcraft III из русского дубляжа 2002–2003, другие игры), описаны в
[docs/voices.md](docs/voices.md) и [docs/voices-wc3.md](docs/voices-wc3.md), но в репозиторий не входят. Голоса
реальных людей — только для шуток на стриме: не выдавайте синтез за их настоящие слова.

Как подбираются образцы (варианты, синтез тестовых фраз, оценки и модель эмоций, выбор на слух на локальной
странице, установка): [docs/voice-pipeline.md](docs/voice-pipeline.md).

Свой набор голосов: положите пары `<имя>.wav` + `<имя>.txt` (точная расшифровка) в папку и выполните
`scripts/import-voices.sh <папка>`. С `--force` скрипт пересобирает уже сохранённые голоса (все или только
перечисленные после флага): сначала выгружает голос из памяти сервера, иначе тот отвечает 409 на повторное имя.

### Озвучка наград Twitch (`stream-tts`)

Основной сервис, cosyvoice-server работает внутри него: зритель активирует награду за баллы канала, вводит текст, и
тот звучит на стриме выбранным голосом (как в JeetBot TTS). Полная спецификация: [docs/stream-tts.md](docs/stream-tts.md).
Установка — [выше](#установка).

Интерфейс: **http://localhost:8090**. Дальше всё в нём:
1. **Twitch** → гайд по шагам: 2FA, своё приложение на dev.twitch.tv (Client Type: **Public**), Client ID.
   Вход по коду на twitch.tv/activate, канал берётся из токена. Затем «Как зрители заказывают озвучку»:
   награда за баллы («Создать награду»), команда в чате (`!tts текст`, с кулдаунами) и/или все сообщения чата,
   у каждого способа свой уровень доступа и список ников, которым он доступен всегда.
   Без 2FA — режим «Только чтение чата»: только ник канала, без приложения и входа; доступны команда и все
   сообщения чата, награды нет.
2. **Очередь** → адрес оверлея `http://localhost:8090/overlay`: OBS → Источник → Браузер.
   В обычной вкладке нужен клик «Включить звук». Там же тестовая активация (весь путь, кроме Twitch).
   Страница голосов для зрителей: кнопка «Открыть» выкладывает её в интернет через туннель Cloudflare (без аккаунта
   и хостинга, пока запущена программа; адрес меняется при каждом запуске, зрители получают его командой
   `!ttsvoices`). Постоянный адрес — zip для своего хостинга: `/voices.zip`.
3. **Голоса** → включение, поправка громкости, «послушать».

Команды в чате: `!tts <текст>`, если включена команда озвучки (имя меняется), `!ttssf <голос>` (зритель
выбирает голос), `!ttsvoices` (ссылка на страницу голосов), для модеров и стримера `!ttsskip`, `!ttsclear`,
`!ttsban <ник>`, `!ttsunban <ник>`, `!ttson`, `!ttsoff`.

Переменные `.env` (все необязательные: порт, пароль админки, язык, адрес cosyvoice, Client ID) — в
[docs/stream-tts-deploy.md](docs/stream-tts-deploy.md#переменные).

Данные лежат в `./stream-tts-data` (в git не попадает): `settings.json`, `token.json`, `stream-tts.sqlite`
(история за 30 дней), `profanity.txt` (корни мата, правится и из интерфейса), `demos/` (mp3-примеры голосов).

Программа для Windows без Docker и Python — [в начале](#программа-для-windows).

### Вторая модель: ESpeech

Кроме CosyVoice3, stream-tts умеет озвучивать моделью [ESpeech](docs/espeech.md) (F5-TTS, дообученная на русской
речи, ударения расставляет RUAccent). Она звучит естественнее, но первый звук приходит позже; английский текст читает
с сильным акцентом. Для стрима нужна видеокарта NVIDIA: на процессоре ESpeech слишком медленная. Памяти ей нужно
~1,5 ГБ ОЗУ и ~0,9 ГБ видеопамяти.

- **Поставить.** Вкладка «Загрузки» → карточка «ESpeech» → «Скачать»: Python с PyTorch и модель, ~2,3 ГБ загрузки
  (в Docker — в тома `./espeech-runtime` и `./models`, пересборка образа их не трогает). Потом выбрать ESpeech в
  «Модели синтеза» на вкладке «Сервер» (первая скачанная модель выбирается сама). Работает одна модель за раз;
  переключаться можно когда угодно.
- **Голоса.** У ESpeech свои файлы голосов (`.espeech`): коллекции `voice-sets/espeech/<набор>.zip` ставятся на
  вкладке «Голоса», в «Наборах голосов», рядом с коллекциями CosyVoice ([docs/voices.md](docs/voices.md)). Свой голос из записи — «+
  Добавить голос» на вкладке «Голоса». Ударения в трудных словах — карточка «Словарь ударений» на вкладке «Сервер».
- **Обучить LoRA.** Кнопка «LoRA» у голоса на вкладке «Голоса»: добавьте от минуты реплик этого голоса с точным
  текстом, нажмите «Начать обучение», послушайте результат и «Сохранить в голос». Тембр и манера становятся ближе к
  оригиналу, чем по одному образцу. На RTX 3060 Ti 3000 шагов — около 15 минут; нужно ~3,5 ГБ видеопамяти, с
  «Экономией видеопамяти» — ~1,3 ГБ. Подробнее: [docs/stream-tts.md](docs/stream-tts.md#голоса) и
  [docs/stream-tts-windows.md](docs/stream-tts-windows.md#обучение-lora).

### Третья модель: Supertonic 3

[Supertonic 3](docs/supertonic.md) (Supertone) — лёгкая модель, которая работает только на процессоре: видеокарта
остаётся игре и OBS, памяти нужно ~0,5 ГБ, фраза из награды синтезируется за ~2 с (Ryzen 5 5600G). Голосов у неё
ровно 10 готовых — `anton`, `boris`, `gleb`, `oleg`, `pavel` (мужские) и `anna`, `vera`, `nina`, `olga`, `rita`
(женские); своих голосов из записи она не делает, LoRA и словаря ударений у неё нет.

- **Поставить.** Вкладка «Загрузки» → карточка «Supertonic 3» → «Скачать» (~380 МБ с Hugging Face; в Docker — в
  том `./models`), потом выбрать Supertonic 3 в «Модели синтеза» на вкладке «Сервер». Готовые голоса ставятся сами набором `supertonic`, зрители
  выбирают их так же: `!ttssf anna`.
- **Лицензия.** Веса — BigScience OpenRAIL-M: перед загрузкой программа показывает условия, текст лицензии лежит рядом
  с моделью (`models/supertonic/LICENSE`). Нельзя выдавать себя за другого человека без согласия, травить и
  порочить людей; озвучку нужно помечать как созданную машиной — например, в описании канала. Поэтому модели нет ни в
  установщике, ни в образе Docker.

### Перенос голосов между инстансами

Голос в `voices/<имя>.gguf` — самодостаточный файл размером около 120 КБ. В нём хранятся мел-спектрограмма образца,
эмбеддинг говорящего (CAM++), речевые токены и текст расшифровки, а весов модели нет. Поэтому:

- для переноса достаточно скопировать `.gguf` в папку `voices/` другого инстанса и перезапустить его
  (`docker compose restart`). ONNX-фронтенд там не нужен;
- файл работает с любым квантом CosyVoice3 (Q8_0, Q6_K и т.д.), но не с другими семействами моделей, например CosyVoice2;
- голоса, созданные через WebUI или API без **Save speaker**, живут только в памяти и пропадут после перезапуска.

Если формат голосов сменится в новой версии cosyvoice.cpp, их можно пересобрать из исходных образцов, поэтому
пары `<имя>.wav` + `<имя>.txt` стоит хранить: `scripts/import-voices.sh <папка>` для каждого набора (в этом проекте
образцы лежат в `voice-refs/cosyvoice/<набор>`). Здесь фронтенд уже нужен: файлы в `models/frontend-onnx/`, а
загружает его в сервер сам скрипт.

## Производительность

Замер на Ryzen 5 5600G (6 ядер, 12 потоков) и RTX 3060 Ti 8 ГБ, квант Q8_0:

| Задача | Устройство | Длина аудио | Время генерации |
|---|---|---|---|
| zero-shot | CPU | 8,5 с | ~36 с |
| instruct | CPU | 11,1 с | ~54 с |
| zero-shot | GPU | 6,7 с | ~2,1 с |
| instruct | GPU | 8,3 с | ~2,1 с |

Скорость — RTF, время синтеза / длина звука (меньше 1 — быстрее звучания). На CPU RTF около 4. Этого хватает для
подготовки озвучки, но не для живого диалога. На GPU RTF 0,25–0,33, а короткая фраза занимает 1,5–2,5 секунды.
Ограничение до 6 потоков на CPU (по числу физических ядер) работало медленнее, поэтому используется значение по умолчанию, то есть все потоки.
Чтобы звук начинал играть быстрее, включите в WebUI потоковый режим (Streaming) с форматом MP3 или Opus.

## Решение проблем

| Симптом | Причина и решение |
|---|---|
| `Docker daemon не запущен` | Запустите Docker Desktop. |
| `CPU без AVX2` | Процессор не поддерживается рантаймом. |
| `bash\r: No such file or directory` | Скрипты сохранены с CRLF. Исправить: `sed -i 's/\r$//' *.sh`. Репозиторий защищён `.gitattributes`. |
| Извлечение голоса недоступно | Нет файлов в `models/frontend-onnx/`: `scripts/download-model.sh --frontend int8`. |
| Сервер не стартует, несколько моделей | Выберите модель в админке (вкладка «Сервер»). |
| Модель не качается | Скачайте вручную с Hugging Face в `models/` (см. раздел «Модели»). |
| `Docker не видит GPU` | Обновите драйвер NVIDIA. В Docker Desktop включите бэкенд WSL2, на Linux поставьте NVIDIA Container Toolkit. Проверка: `docker run --rm --gpus all ubuntu:26.04 nvidia-smi`. |
| На GPU тихий шумный звук или мусор вместо речи | Нет `GGML_CUDA_DISABLE_GRAPHS=1` или включён `--llm-flash-attn` ([docs/development.md](docs/development.md#образы)). |
| В начале фразы лишний звук («точка», «пой») | Особенность модели, бывает и на CPU, примерно в 1 фразе из 8. Сгенерируйте заново с другим `seed`. |
